# PlayFunPay — Seller Hub

Полноценный Telegram-бот для сообщества продавцов цифровых товаров и услуг на FunPay. Стек: Python 3.11+, aiogram 3.x, aiosqlite, SQLite, опционально Redis и Telegram Stars.

## Что внутри

### Для пользователей
- Единое меню PlayFunPay, личный кабинет и настройки уведомлений.
- Калькулятор чистой прибыли, маржинальности и ROI.
- Реверс-калькулятор цены лота под нужную сумму на руки с округлением вверх до копейки.
- Игровой налог в двух режимах: «покупатель должен получить X» и «передаю X — сколько дойдёт».
- История расчётов: 5 последних записей бесплатно, до 50 для VIP.
- Проверка описаний на рискованные формулировки и ссылки.
- Конструктор описания лота с пятью шагами.
- Словарь, каталог гайдов и шаблоны ответов покупателям.
- Предложка, реклама, поддержка и репорты с текстом и вложениями.
- Реферальная ссылка для привлечения новых пользователей.
- VIP-доступ на 30 дней через Telegram Stars (XTR).

### Для администраторов
- Доступ к админ-панели только для ID из `ADMIN_IDS`.
- Статистика пользователей, активности, VIP, расчётов, проверок, обращений и оплат.
- Просмотр новых обращений, ответы пользователям и отметка рассмотрения.
- Сегментированная рассылка (всем / новости / советы) с предпросмотром и подтверждением.
- Обработка `TelegramForbiddenError` и `TelegramRetryAfter`.
- Журнал административных действий.

## Быстрый запуск на Windows

1. Установите Python 3.11 или новее.
2. Распакуйте архив и откройте PowerShell в папке проекта.
3. Создайте виртуальное окружение и установите зависимости:

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

4. Скопируйте шаблон окружения и заполните токен и ID администратора:

```powershell
Copy-Item .env.example .env
notepad .env
```

5. Запустите:

```powershell
python main.py
```

## Проверка расчётной логики

```powershell
python -m unittest discover -s tests -v
```

## Запуск на Linux VPS

```bash
sudo apt update
sudo apt install -y python3 python3-venv
mkdir -p /opt/playfunpay
cd /opt/playfunpay
# Загрузите и распакуйте архив проекта сюда.
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
nano .env
python main.py
```

Для постоянной работы создайте `/etc/systemd/system/playfunpay.service`:

```ini
[Unit]
Description=PlayFunPay Telegram Bot
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/playfunpay
ExecStart=/opt/playfunpay/.venv/bin/python /opt/playfunpay/main.py
Restart=always
RestartSec=5
User=www-data

[Install]
WantedBy=multi-user.target
```

Затем проверьте права на папку `data` и `.env`, после чего выполните:

```bash
sudo chown -R www-data:www-data /opt/playfunpay
sudo chmod 600 /opt/playfunpay/.env
sudo systemctl daemon-reload
sudo systemctl enable --now playfunpay
sudo journalctl -u playfunpay -f
```

## Docker Compose + Redis

1. Установите Docker Engine и Compose plugin.
2. Заполните `.env`.
3. В `.env` задайте `REDIS_URL=redis://redis:6379/0`.
4. Выполните:

```bash
docker compose up -d --build
docker compose logs -f bot
```

SQLite хранится в `./data`, FSM-состояния сохраняются в Redis.

## Настройка Telegram

1. Создайте бота через `@BotFather` и получите `BOT_TOKEN`.
2. Узнайте свой Telegram ID (например, через `@userinfobot`) и внесите его в `ADMIN_IDS`.
3. При необходимости добавьте бота в закрытую группу модерации и задайте `SUBMISSIONS_CHAT_ID`.
4. Для VIP используется Telegram Stars в валюте `XTR`; внешний платёжный провайдер не используется.
5. Проверьте корректность стоимости в `VIP_PRICE_STARS`. По умолчанию — 299 Stars за 30 дней.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен от BotFather |
| `ADMIN_IDS` | ID администраторов через запятую |
| `CHANNEL_URL` | Ссылка на основной канал |
| `CHANNEL_USERNAME` | Username канала |
| `SUBMISSIONS_CHAT_ID` | Необязательный чат модерации |
| `REQUIRE_SUBSCRIPTION` | Мягкая проверка подписки на дополнительный канал |
| `OPTIONAL_SUB_CHANNEL_ID` | ID дополнительного канала для контроля подписки |
| `DEFAULT_FEE_PERCENT` | Процент удержаний по умолчанию в конфигурации |
| `DEFAULT_GAME_TAX_PERCENT` | Игровой налог по умолчанию в конфигурации |
| `VIP_PRICE_STARS` | Стоимость VIP в Telegram Stars |
| `BROADCAST_DELAY` | Пауза между сообщениями рассылки |
| `DATABASE_PATH` | Путь к SQLite |
| `REDIS_URL` | Redis для FSM; оставьте пустым для MemoryStorage |
| `LOG_LEVEL` | Уровень логирования |

## Модель монетизации

VIP в текущей версии даёт расширенную историю расчётов (до 50 вместо 5) и отметку VIP в профиле. Цена и срок задаются в конфигурации и обработчике платежей. Реферальная система считает приглашённых пользователей, но автоматические денежные выплаты реферерам не реализованы. Не обещайте участникам выплаты по реферальной ссылке.

Перед публичным запуском проверьте покупку VIP на тестовом боте и небольшую сумму Stars. Возвраты платежей и полноценный финансовый кабинет администратора для них нужно реализовать отдельно.

## Ограничения и безопасность

- Сканер — эвристический локальный словарь, не официальный валидатор FunPay и не гарантия прохождения модерации.
- Процент удержаний вводит пользователь; бот не выдаёт его за официальный тариф площадки.
- Мягкая проверка подписки включается `REQUIRE_SUBSCRIPTION=true` и `OPTIONAL_SUB_CHANNEL_ID`. Бот должен быть администратором указанного канала, чтобы получать достоверный статус участника. При ошибке Telegram API проверка пропускает пользователя, чтобы случайно не закрыть всем доступ.
- Реферальный счётчик засчитывает только первое создание профиля с реферальным параметром; он не выплачивает вознаграждения.
- Не храните токены и секреты в Git. Делайте резервные копии `data/playfunpay.db`.
- Для большой аудитории рекомендуется PostgreSQL, Alembic-миграции, мониторинг, бэкапы и отдельная очередь рассылок вместо долгого цикла внутри polling-процесса.
- Бот может писать только пользователям, которые сами открыли его и нажали `/start`. Подписчики канала автоматически не становятся пользователями бота: разместите ссылку на бота в закрепе, описании и рекламных публикациях.
- Текущая рассылка предназначена для небольших и средних баз пользователей. Для сотен тысяч/миллиона адресатов нужна отдельная очередь задач с возобновлением, контролем лимитов и несколькими worker-процессами.
